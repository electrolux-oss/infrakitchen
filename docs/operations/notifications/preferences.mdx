title: Notification Preferences
---

Every notification is delivered **in-app** by default. Notification Preferences let you also receive an event type through an external channel such as Slack. Each preference maps one event type to one or more additional channels.

## Overview

A **Notification Preference** answers the question: _"When event X happens, where else should I be notified?"_

You can have one preference per event type. Without a preference you still receive the event in-app; the preference only adds the selected channels.

:::tip[Preferences and Subscriptions work together]
[Subscriptions](subscriptions) (and being an approver or the author of a change) decide **which** notifications you receive; preferences decide **where else** they are delivered.
:::

You can open your preferences from your **User Profile** (**Notifications** tab), or with the **Preferences** button in the subscribe popover on a resource, project or service.

## Viewing Your Preferences

<Steps>

<Step title="Open your User Profile">

Navigate to your **User Profile** and open the **Notifications** tab.

</Step>

<Step title="Find the Notification Preferences card">

The **Notification Preferences** card is the first card on the tab.

</Step>

<Step title="Review your preferences">

The table shows all your configured preferences with their event type, additional channels, and creation date.

</Step>

</Steps>

## Adding a Notification Preference

<Steps>

<Step title="Click Add Preference">

In the **Notification Preferences** card, click <kbd>Add Preference</kbd>. A dialog opens with two fields.

</Step>

<Step title="Configure the preference">

- **Event Type** — Select the event you want to receive outside the app
- **Additional channels** — Select one or more external channels

</Step>

<Step title="Create">

Click <kbd>Create</kbd>.

</Step>

</Steps>

### Event Types

| Event Type          | Description                                                                                |
| ------------------- | ------------------------------------------------------------------------------------------ |
| `update`            | An entity's status changed, e.g. it was edited, approved, rejected, destroyed or recreated |
| `execute`           | An operation (apply, plan, sync, ...) finished on an entity                                |
| `approval_required` | A resource you can approve is waiting for approval                                         |
| `approval_result`   | A change you requested was approved or rejected                                            |

### Additional Channels

| Channel   | Description                                                                                                 |
| --------- | ----------------------------------------------------------------------------------------------------------- |
| **SLACK** | Notification is sent to Slack via the configured [Slack integration](../../integrations/notification#slack) |

:::info[At least one channel required]
You must select at least one additional channel when creating or editing a preference. In-app delivery is always on and cannot be selected.
:::

:::note[Linking your Slack account]
Slack messages are only delivered once your InfraKitchen account is linked to your Slack user. Until then, Slack preferences in the table are marked with a warning icon, and the **Add Preference** / **Edit** dialog shows a **Link Slack account** button. You can also link it with **Sync Slack** in the overview at the top of your profile. Linking matches your InfraKitchen email to a user in the Slack workspace of the integration.
:::

## Editing a Preference

In the **Notification Preferences** table, click the edit (pencil) icon in the **Actions** column of the row you want to change, update the **Additional channels**, and save. The event type of an existing preference cannot be changed; delete it and add a new one instead.

## Deleting a Preference

In the **Notification Preferences** table, click the delete (trash) icon in the **Actions** column of the row you want to remove, then confirm with the check icon.

After deletion you keep receiving that event type in-app, but no longer through the removed channels.

## Preference Properties

| Property       | Description                                                          |
| -------------- | -------------------------------------------------------------------- |
| **Event Type** | The event that triggers the notification (e.g., `update`, `execute`) |
| **Channels**   | The additional channels enabled for this event type                  |
| **User**       | The user who owns this preference                                    |
| **Created At** | When the preference was created                                      |
